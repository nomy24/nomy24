# 提供票チェック

提供票をスキャンして、通所介護のマークがある日を読み取り、
あらかじめ登録した**曜日（午前・午後）**とつき合わせるアプリです。
ちがう日にマークがある、登録した日にマークがない、といったところを一覧で知らせます。

公開先は <https://nomy24.github.io/nomy24/teikyo/> です。
スマートフォンで開いて「ホーム画面に追加」すると、アプリとして起動します。

## 使い方

1. **利用者を登録する**（最初の1回だけ）
   「利用者」タブ → 追加。名前と、通所する曜日を午前・午後まで入れます。
   隔週の人は曜日ごとに「第2・第4」などを選べます。
2. **準備**
   利用者と対象の月を選び、スキャンした画像を取り込みます。
3. **枠合わせ**
   画像の上のオレンジの印を、読みたい行の四隅に合わせます。
   左右は**1日の列の左端**と**31日の列の右端**、上下は読みたい行の上下の罫線です。
   囲んだ行が上から何なのか（実績・午前／実績・午後 など）を選びます。
4. **確認**
   読み取った結果が出ます。ちがうところはマスを押すと直せます。
   点線のマスは「どちらとも言いにくい」ところなので、とくに見てください。
5. **結果**
   登録した曜日と照らした結果が出ます。「結果を保存する」で履歴に残ります。

## 知らせるちがい

| 出るもの | どんなとき |
| --- | --- |
| 予定外の利用 | 登録していない日に、提供票のマークがある |
| マークなし | 登録した利用日なのに、提供票にマークがない |
| 時間帯ちがい | 日は合っているが、午前・午後がちがう |
| 予定と実績のちがい | 予定の行と実績の行の両方を読んだときに、その2つがずれている |

その月だけの追加や休みは、結果の画面で「この月だけ提供票に合わせる」を押すと登録できます。
次からその日は知らせません。

## 読み取りの仕組み

文字を読む OCR ではありません。
四隅から表の位置を割り出し（写真の傾きは射影変換で直します）、
マス目に等分してから、**マスの中がどれだけ濃いか**でマークの有無を決めています。
提供票のマークは印字の「1」だったり手書きの丸だったりして形が定まらないので、
形を当てにせず濃さだけを見るほうが、この用紙ではよく当たります。

- 紙と墨の境目は、用紙全体の明るさから自動で決めます（大津の方法）。
- 影で暗くなったところは、マスごとの紙の明るさで打ち消します。
- マークの有無の境目も、読み取った濃さの分かれ目から自動で決めます。
- それでも合わないときは「感度」で調整し、最後はマスを押して直せます。

## 保存とプライバシー

- 提供票の画像は**この端末の中だけ**で処理します。どこにも送りません。
- 画像そのものは保存しません。残るのは「何日にマークがあったか」という結果だけです。
- 利用者と履歴は、この端末の localStorage に保存します。ほかの端末とは共有されません。
  端末を替えたときや、ブラウザのデータを消したときは残りません。
- 全部消したいときは、右上の設定から「保存したデータを全部消す」を押します。

## 気をつけること

- 読み取りは目安です。**最後は必ず提供票そのものでご確認ください。**
- 祝日は見ていません。祝日休みの事業所では、その日は「マークなし」として出ます。
  その月だけの休みとして登録すると消えます。
- 提供票の用紙は31列が基本です。30日までの月は、31日の欄にマークが出たら枠のずれを疑ってください
  （そのときは結果の画面にも注意書きが出ます）。

## ファイル

```
index.html    画面
app.css       見た目
app.js        画面の組み立てと、読み取り〜照合の流れ
scan.js       画像からマスを切り出してマークを読む
schedule.js   曜日パターンから利用日をつくり、読み取り結果と照らす
store.js      端末内の保存（利用者・履歴・設定）
sw.js         オフライン表示用のキャッシュ
```

ビルドはありません。ファイルを置き換えればそのまま反映されます。
画面のファイルを直したときは、`sw.js` の `VERSION` を上げると、古いキャッシュが残りません。
