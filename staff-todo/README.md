# 職員Todo

職員同士で **Todo・カレンダー・定型タスク（毎日／月初／月末／随時）** を共有できる、スマートフォン向けの Web アプリです。

## できること

| 機能 | 内容 |
| --- | --- |
| Todo | タイトル・メモ・担当（複数選択・職種グループでまとめて選択可）・期限・優先度を付けて共有。日付ごとにグループ表示され、検索で完了済みもさかのぼって探せる |
| カレンダー | 月表示。日付をタップするとその日の予定がウィンドウで確認でき、下部には月全体の予定が日付ごとにまとまる |
| 定型タスク | 「毎日」「月初」「月末」「随時」の4種類でチェックリストを管理。月初・月末は期間（開始日〜終了日）を指定でき、その期間になると対応するTodoが自動で追加される |
| 資料 | 写真・PDF・文書ファイルを貼り付け/アップロードして保存。日付・月ごとにまとまる |
| 電話メモ | 受けた電話の要件・対応状況（未対応/対応中/完了）を記録・共有。未対応件数はタブに数字バッジで表示 |
| 設定 | 自分の名前・職種グループを選ぶと、担当や実施者として記録される。文字を大きくする、ヘッダーを隠す、端末を再ロックする、などの表示・セキュリティ設定もあり |

自分以外が追加した新着項目には「NEW」タグが付き、見落としを防ぎます。またアプリを開く際は、共有モードでは職員ごとのメールアドレス・パスワードでのログインが、お試しモードでは合言葉の入力が必要です（詳しくは下記「注意事項」）。

デザインは、あじさい色の「南区インフォ」とは別系統の、明るいティール（緑がかった水色）とオレンジを使った、はっきり見やすい配色にしています。スマートフォン優先のレイアウトで、ホーム画面に追加すればアプリのように使えます（PWA）。

## 使い方（今すぐ試す）

Firebase を設定しなくても、そのままアプリとして動きます。ただしこの場合は **お試しモード** となり、データはその端末（スマホ）の中だけに保存され、他の職員とは共有されません。

まずはこの状態で操作感を確認し、問題なければ次の「共有モードにする」に進んでください。

## 共有モードにする（4人でデータを共有する）

4人のスマホでリアルタイムに同じデータを見られるようにするには、無料の Firebase プロジェクトを1つ作成し、発行される設定値をこのアプリに設定します。所要時間の目安は5分程度です。

### 1. Firebase プロジェクトを作る

1. [Firebase コンソール](https://console.firebase.google.com/) を開き、Google アカウントでログインする
2. 「プロジェクトを追加」→ 名前を入力（例：`staff-todo`）→ 作成する（Google アナリティクスは無効のままでよい）

### 2. Firestore を有効にする

1. 左メニューの「構築」→「Firestore Database」を開く
2. 「データベースを作成」→ ロケーションは `asia-northeast1`（東京）を選ぶ
3. モードは「本番環境モード」を選んで作成する

作成後、「ルール」タブを開き、以下の内容に置き換えて「公開」する。これは「職員として実際にログインした人だけが読み書きできる」という設定です（`sign_in_provider != 'anonymous'` の部分で、パスワードなしの匿名アクセスを弾いています）。

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /{document=**} {
      allow read, write: if request.auth != null
        && request.auth.token.firebase.sign_in_provider != 'anonymous';
    }
  }
}
```

### 3. 職員ごとのログインを有効にする

1. 左メニューの「構築」→「Authentication」を開く
2. 「始める」→「Sign-in method」タブ →「メール / パスワード」を選んで有効にする
3. 「Users」タブ →「ユーザーを追加」で、職員1人につき1つ、メールアドレスとパスワードを手動で登録する（本人の実在メールでなくてもよいが、他の職員と重複しない値にする）

アプリを開くと、このメールアドレスとパスワードの入力を求めるログイン画面が表示されます。アカウントを持たない人（匿名アクセス）は上記のルールにより Firestore を読み書きできません。パスワードを忘れた・アカウントを増やしたい場合は、管理者がこの Users 画面から変更してください。

### 4. アプリに設定値を入れる

1. Firebase コンソールの左上の歯車アイコン →「プロジェクトの設定」を開く
2. 「マイアプリ」→ `</>`（ウェブ）のアイコンでアプリを追加する（アプリ名は何でもよい。Firebase Hosting は不要）
3. 表示された `firebaseConfig` の値一式をコピーする
4. このフォルダの `firebase-config.js` を開き、`REPLACE_ME` の部分を実際の値に書き換えて保存する

```js
export const firebaseConfig = {
  apiKey: "ここに値",
  authDomain: "ここに値",
  projectId: "ここに値",
  storageBucket: "ここに値",
  messagingSenderId: "ここに値",
  appId: "ここに値",
};
```

保存すると、アプリは自動的に「共有モード」に切り替わります（設定画面の「共有の状態」で確認できます）。

### 5. 公開して4人で使う

GitHub Pages を有効にすると、そのまま公開できます。

1. リポジトリの **Settings › Pages** を開く
2. **Source** で `Deploy from a branch` を選び、ブランチ `main` / フォルダ `/ (root)` を指定
3. 数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/staff-todo/` で開けるようになる

このURLをLINEなどで4人に共有してください。スマートフォンでURLを開き、共有メニューから「ホーム画面に追加」すると、アプリのように起動できます。

## 注意事項（セキュリティについて）

- **共有モード**（Firebase 設定済み）では、職員ごとのメールアドレス・パスワードでのログインが必須です。アカウントは管理者が Firebase コンソールの Authentication → Users で発行してください（上記「3. 職員ごとのログインを有効にする」）。Firestore のルールも、ログイン済みかつ匿名アクセスではないユーザーだけに絞ってあるので、アカウントを持たない第三者はデータを読み書きできません。
- **お試しモード**（Firebase 未設定）では、初回起動時に決める「合言葉」で入口を塞ぎます。こちらはブラウザ上でのチェックのみの簡易的な対策で、データはその端末の中だけに保存されます。
- 病歴・個人情報など、機微な情報の記録には使わないでください。
- 「資料」で追加できるPDF・文書ファイルは、Firestore の1ドキュメントあたりの上限（1MiB）に収まるよう700KBまでに制限しています。写真は自動で圧縮されるため、通常はこの制限を意識する必要はありません。
- データを削除・作り直したい場合は、Firebase コンソールの Firestore Database から該当のコレクション（`staff` / `todos` / `events` / `routineTasks` / `routineLogs` / `groups` / `photos` / `phoneMemos` / `appConfig`）を削除してください。

## ファイル

```
staff-todo/
  index.html            画面
  app.css                配色・レイアウト
  app.js                 画面の動作
  store.js                データの保存・同期（Firestore / お試しモードの切り替え）
  firebase-init.js        Firebase の初期化・ログイン（メール / パスワード）
  firebase-config.js       Firebase の設定値（ここを書き換えて共有モードにする）
  sw.js                    オフライン表示用キャッシュ
  manifest.webmanifest     ホーム画面に追加するための設定
  icons/                   アプリアイコン
```
