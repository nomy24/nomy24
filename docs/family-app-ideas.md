# 家族3人（親2人・娘1人）向け アプリ開発テーマ

このリポジトリの資産（ビルド無しの HTML/CSS/JS、GitHub Pages、Firestore 共有、
GitHub Actions での定期取り込み）の上に載せる前提で、次に作るアプリの候補をまとめたものです。
娘さんの年齢が決まっていないので、年齢帯のめやすを付けています。

## おすすめ順

### 1. 家族ボード（買い物リスト＋予定＋持ち物）← 本命

`staff-todo/` をほぼそのまま流用できます。新規開発というより
「職員4人向け → 家族3人向けに削る」作業なので、いちばん早く完成して、
いちばん毎日使われます。

| 職員Todo の機能 | 家族ボードでの役割 |
| --- | --- |
| Todo | 買い物リスト・やることリスト |
| カレンダー | 家族の予定（習い事・行事・当番） |
| 定型タスク | ゴミ出し、曜日ごとの持ち物 |
| 電話メモ | 学校・園からの連絡メモ |

- 流用元: `staff-todo/store.js`（Firestore / お試しモードの切り替え）、
  `staff-todo/app.js` の共有・NEWタグ、`staff-todo/firestore.rules` の権限モデル
- 削るもの: 職種グループ、資料アップロード、管理者まわり。
  担当は「パパ / ママ / 娘」の3つ固定でよい
- 年齢: 全年齢（低学年以下なら、リストは親が入れて娘さんはチェックだけ）

### 2. おてつだいスタンプ＆おこづかい

娘さんが「使う側」になれる唯一のテーマです。
ボタンを押す → スタンプが増える → 月末に集計、という単純なループで成立します。

- 中身: おてつだい項目（お皿ふき 10円 など）をタップで記録 / 今月の合計 /
  月末リセット / 達成グラフ1枚
- 流用元: `staff-todo` の定型タスクと `routineLogs` の考え方
- 年齢: 未就学〜小学生。文字が読めない年齢なら絵文字の大きなボタンで作る

### 3. 相模原こそだてフィルター（南区インフォの派生）

`sagamihara-minami/scripts/fetch-news.mjs` と GitHub Actions（1日2回）が
すでに動いているので、取り込み基盤を新しく書く必要がありません。

- やること: `sagamihara-minami/config/sources.json` と
  `scripts/lib/classify.mjs` に子育て系カテゴリ（検診・予防接種・学校・
  子どもイベント・図書館）を足し、その分類だけを表示する画面を作る
- コスト感: 3案の中で最小。設定ファイル＋分類ルール＋表示の絞り込みだけ
- 年齢: 親向け（娘さんは使わない）

## 次点

| テーマ | ひとこと | 流用 |
| --- | --- | --- |
| 献立ボード | 1週間の献立を決めると買い物リストへ自動変換。ネタ切れ解消に効く | 1番の拡張として作るのが正解 |
| 成長きろく | 写真1枚＋一言を日付順に。年ごとに振り返る | `staff-todo` の「資料」（写真圧縮・700KB制限）がほぼ完成品 |
| あしたの準備チェック | 曜日ごとの時間割・持ち物チェック。朝の「あれ持った?」が消える | 定型タスクの曜日版 |
| 漢字・計算ドリル | 娘さんと一緒に問題を作れる | `drill/index.html` の単一ファイル構成 |

## 選ぶときの目安

- すぐ使われる物が欲しい → **1番**。既存コードの削り込みで、新規実装が最も少ない
- 娘さんと一緒に楽しみたい → **2番**。ただし新規UI（スタンプ表示・集計）が多い
- 手を動かす量を最小にしたい → **3番**。バックエンド（Actions）がすでにある

## Firebase をどうするか

Firestore を使う場合、無料プロジェクトを増やすより
`staff-todo` と**同じプロジェクトにコレクションを分けて相乗り**するほうが管理が楽です。

ただし `firestore.rules` は、職員用と家族用でログインアカウントの集合が違います。
相乗りさせるなら、コレクションごとに条件を分けて書く必要があるので、
そこだけは作りはじめる前に決めておいてください。
