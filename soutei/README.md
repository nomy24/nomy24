# デイサービス送迎表

車両8台（5人乗り6台・7人乗り2台）の送迎ルートを、**午前・午後 × お迎え・お送りの全4便**として管理する運行表。
印刷すると1便＝A4横1枚、合計4枚になる。業務日誌は日誌と検温のA4横2枚。
`index.html` の1ファイルで完結（外部CSS・JS・フォントなし）。ブラウザで開いてそのまま印刷できる。

## 表題と日付

見出しは日付と一体で **「令和8年7月27日（月曜日）送迎表」** の形。和暦は令和・平成・昭和に対応。

日付を動かす口は3つある。

- **見出しの日付そのものがプルダウン**（`▾` が目印）。保存済みの日が新しい順に並び、選べばその日に切り替わる。
- 見出しの右の **「別の日を開く」** の日付欄。ここに入れれば、まだ保存していない日でも開ける。
- その日付欄の **左右の矢印（`‹` `›`）**。1日ずつ前後に動く。連日の表を続けて作るときに速い。

どれを使っても、他の表示は追従する。
ページを開いたときは常に**本日**から始まる（毎日の運用でそのまま使えるように）。
別の日で作業していた場合は、上の2つの口から戻ってほしい。

## スクロールしても残るもの

上に貼り付くのは **いま開いている便の見出しの行（便名・経路・人数）** だけ。
車両カードを広く見せたいので、表題やツール列は一緒に流れる（上へ戻せば出てくる）。

便の切替は、**画面の左の未割当サイドバー**からいつでもできる。こちらもスクロールに追従する。

印刷では固定を解いて通常の流れに戻る。

## 一つ戻る／一つ進む

ツール列の **「↶ 一つ戻る」「↷ 一つ進む」** で、その日の表への操作をさかのぼれる。
`Ctrl`（Mac は `⌘`）+ `Z` と `Ctrl`+`Shift`+`Z` でも同じ。

- 対象はページ全体（全4便の記入内容）で、区切りは自動保存のタイミング。
  連続した打鍵はひとまとめになる。
- **日付を切り替えると履歴は作り直される**（その日の入り口が起点になる）。
- 直近60手まで。

## 日付ごとの保存

記入内容は**日付ごとに自動保存**される。日を切り替えても、ブラウザを閉じて開き直しても、
その日の内容がそのまま戻る。過去の日を選べば当日どう組んだかを見返せる。

保存先はブラウザの localStorage で、鍵は次のとおり。

| 鍵 | 中身 |
| --- | --- |
| `soutei.v2.days` | 保存済みの日付の一覧 |
| `soutei.v2.day.<YYYY-MM-DD>` | その日の全4便の記入内容 |
| `soutei.v2.users` / `soutei.v2.drivers` | 編集後のマスタ |

localStorage が使えない環境では、表題の右に「※ この環境では保存できません」と出したうえで、
その場かぎりの控えに落として動き続ける。

## 端末をまたいで共有する（サーバー保存）

そのままでは同じブラウザの中にしか残らないので、事業所の PC 1台を**保存サーバー**にして共有できる
（`server/soutei-server.js`。立ち上げ方は `server/はじめかた.md`）。
データはその PC の中にだけ置かれ、インターネットには出ない。

### 手元優先・あとから同期

送迎中のタブレットは電波が切れる。常時通信を前提にすると使い物にならないので、
**入力は必ず先に手元へ書き、あとから送る**作りにしてある。

1. 入力 → その場で localStorage に保存（ここは今までどおり）
2. 1.2秒後に裏でサーバーへ送る。8秒ごとに他の端末の変更も見に行く
3. 送れなければ**送信待ちとして手元に残す**。電波が戻った時点で送る

送信待ちの一覧も localStorage に置いてあるので、**圏外のままブラウザを閉じても消えない。**
次に開いたときに送られる。日付の右の表示で状態が分かる。

| 表示 | 意味 |
| --- | --- |
| サーバー保存　共有中 | つながっていて、送るものもない |
| サーバー保存　送信中… | 手元の変更を送っている最中 |
| サーバー保存　つながりません（手元に保存しています） | 圏外・サーバー停止。書いたものは消えない（赤字） |
| 自動保存 | サーバーを使っていない（ファイルを直接開いた場合など） |

### 書き負けを防ぐ

保存の単位は鍵ごと（`day.<日付>` / `users` / `drivers` / `dispatch`）で、それぞれに**版番号**が付く。

- 送るときは「自分が知っている版番号」を一緒に渡す。
- サーバー側の版が進んでいたら**書き込まずに断り**、向こうの内容を返す。
- 受け取った側は画面をその内容に合わせ、「他の端末での変更を取り込みました」と知らせる。
  自分の直前の手は**「一つ戻る」**で取り戻せる。

黙って上書きしないことを優先している。同じ日を2人が同時に組むこと自体は起きるので、
消えたことに気づけないほうが困るため。

### サーバーが無くても動く

起動時に `api/ping` を叩いて、応答が無ければ**これまでどおり手元だけ**で動く。
ファイルを直接ダブルクリックして開いた場合（`file://`）もこちら。作りは1つで、つなぎ先だけが変わる。

### API

| | |
| --- | --- |
| `GET /api/ping` | 生きているかの確認 |
| `GET /api/index` | 鍵ごとの版番号と、保存済みの日付の一覧 |
| `GET /api/doc?key=…` | 中身を取る |
| `PUT /api/doc?key=…` | `{baseRev, data}` を渡す。版が食い違えば `409` と向こうの中身が返る |

保存は `server/data/<鍵>.json` に1件1ファイル。データベースは使っていない。
書きかけが残らないよう、別名で書いてから置き換えている。

**LAN の中だけを想定していて、認証は付けていない。**
外から届く場所に置く場合は、パスワードと https を足す必要がある。

## 4便の構成

| 便 | 経路 | 時刻の起点 | 色 |
| --- | --- | --- | --- |
| 午前 お迎え | 自宅 → 事業所 | **事業所着 08:55〜09:00** から逆算 | 藍 |
| 午前 お送り | 事業所 → 自宅 | 事業所発 12:05（帰着なし） | 柿渋 |
| 午後 お迎え | 自宅 → 事業所 | **事業所着 13:10〜13:20** から逆算（事業所発なし） | 青碧 |
| 午後 お送り | 事業所 → 自宅 | 事業所発 16:30 | 臙脂 |

色は**寒色＝お迎え／暖色＝お送り**で揃えてある。運転手が最初に確認するのは進行方向なので、
そこを色相に、午前・午後を色の系統に割り当てた。刷り上がった4枚を取り違えにくくするための区別でもある。

画面ではタブで切り替え、印刷では4便が別ページになる。日付・便名・合計は各ページのヘッダに入る。

## レイアウトの考え方

送迎表は「時間割」ではなく「車ごとの巡回順」なので、時刻をタテ軸に取ったマトリクスではなく
**車両カード×8を2列に並べる**構成にした。

各カードは左右2カラム。

- **左**：号車の記入枠（または車両名）／**出発位置**の記入枠／乗車定員／運転手の記入枠／
  定員ピップ（`■`＝乗車・`□`＝空席）
- **右**：事業所発のバー、ルート順の行リスト（`順番 / 予定 / 実績 / 利用者名 / 住所 / 記号 / 備考`）、
  そして事業所着（帰着）の記入欄

**備考**欄は玄関先の目印、マンションの部屋番号、門扉の注意など、当日の申し送りを書くところ。
記号の右に置いてあり、印刷にも出る。

**記号は絵**で出す（車椅子・歩行器・扉）。走行前に上から下へ目を落とすとき、文字より速く拾えるため。
読み上げと控えのために、もとの1文字（車・補・玄）は `data-key` と説明文に残してある。
歩行器の絵に車輪を描いてあるのは、小さく刷ったときに「H」に見えないようにするため。

**カードの右上に地図の口**がある。押すと Google マップの経路検索が開き、
`事業所 → 各家（カードの順番どおり）→ 事業所` のルートを表示する。欠席の方は立ち寄らないので外す。
住所は「都道府県（事業所タブで設定）＋ 利用者の住所」で組む。事業所の住所が空だと押せない。
経由地は Google マップの上限に合わせて先頭9か所まで。地図は**開くだけ**で、住所を渡す以外の通信はしない。

**午後お迎えだけは事業所発を持たない。** 午前お送りからそのまま続けて回るので、
出発の記入欄と実績欄は置かず、カードの上端は「午前お送りから続けて」とだけ出す。
時刻は**事業所着（13:20）からの逆算だけ**で決まり、人を足しても引いてもそのつど引き直すので、
上限を超えることがない（調整の口がないぶん、自動で必ず内側に収める）。

**事業所の出発時刻は車両カードごと**に持たせてある。カードの上端で書き換えると、その車の予定時刻が引き直される。
出発時刻の横と各利用者の予定時刻の横には **「実績」欄**があり、実際に着いた時刻を書き込める（自動計算には使わない）。

**号車・運転手・事業所着・帰着の時刻は空欄**。当日の割り当てに合わせて手書きで入れられるよう
枠と罫線だけ置いてある（画面上でも入力できる）。車両ナンバーは載せていない。

運転手は運転手マスタからのプルダウンで選ぶ。同じ便のなかでの重複を防ぐため、

- すでに他の車で選ばれている方は一覧で **「（使用中）」** と薄字になる。
- それでも選ぶと、**元の車から外れてこちらへ移る**（二重に立つことがない）。
- **右クリックで空欄**に戻せる。

**出発位置**は、その車がどこから走り出すかを書く枠。号車枠のある6台にだけ置いてある
（ノア・リフト車は定位置なので省いた）。

7人乗りの2台は日ごとに入れ替わらないので、号車の記入枠のかわりに車両名 **「ノア」「リフト車」** を固定表示する。

カードの中は運転席から目を落として読むものなので、**全体を太字**にしてある（列見出しだけは1段軽くして、
データが前に出るようにした）。

### 介護度

利用者マスタに **介護度** の列がある。`事業対象者 / 要支援1・2 / 要介護1〜5` から選ぶ（未設定のままでもよい）。
送迎表の並びや時刻には使っていない。**出欠と業務日誌の「要介護／介護予防」の振り分け**に使う。

### 血圧（業務日誌の備考欄）

利用者マスタに **血圧** の列がある。`上腕計 / 実測 / 左シャント / 右シャント / 左シャント実測 / 右シャント実測`
から選ぶ。血圧をどう測るかはその方に付いて回る事柄なので、日ごとではなくマスタに持たせている。

業務日誌の **備考欄にそのまま出る**。`シャント` を含むものだけ**赤字**、`上腕計` と `実測` は黒。
測る腕を間違えないための色分けなので、マスタ編集の画面でも同じ色で見せている。

### 事業所の情報

**事業所名は画面の見出しでそのまま直せる**（左上の薄い文字を押して打ち替え、Enter か余白を押せば確定。
Esc で取り消し）。直した名前は印刷の見出しにも出て、マスタにも入る。

マスタ編集の **「事業所」** タブには3つ。

| 項目 | 使いみち |
| --- | --- |
| 事業所名 | 画面の表題と、印刷したときの見出し |
| 事業所の住所 | 地図のルートの**出発地と到着地** |
| 都道府県 | 地図に渡すときだけ、利用者の住所の前に付ける。利用者マスタの住所は**市区町村から**入れる（例：〇〇市中央町3-14-2） |

### 車椅子が乗る車両

**リフト車**に記号 `車` の行があると、そのカードは**朱色**に変わり、**定員が1名減る**（6名 → 5名）。
車椅子がスペースを1席ぶん使うため。定員ピップも1つ減り、超えれば `⚠ 定員超過` が出る。記号を外せば元に戻る。

**この定員の増減はリフト車だけに効く。** 他の車で `車` を付けても記号は表示されるが席は減らないので、
4名乗車のところで `4 / 3 名` のような偽のエラーにはならない。
どの車両をリフト車として扱うかは `FLEET` の `lift: true` で決める。

朱色は地色と文字色だけで、枠線は通常のまま。エラーの赤（定員超過・欠席・重複）とは別の色にしてあり、
「注意して見る車」の合図として働く。

## 利用者の選択と住所の自動反映

利用者名の欄は利用者マスタ（`USERS`）を引いたプルダウン。**その日の曜日・その便（午前／午後）に来る方だけ**が並び、
さらに**町名ごとの optgroup** にまとめてあるので、ルートを組む順序（地区をまたがない）のまま選んでいける。

町名はマスタに持たせず、**住所から自動で拾う**（`TOWNS` に載っている町名が住所に含まれていればそれ）。
住所は「〇〇市中央町3-14-2」のように**市区町村から**入れる。
`TOWNS` に無い住所は **「その他」** にまとめ、事業所からの平均的な位置で見積もる。
実際の住所で運用するときは `TOWNS` に町名と座標を足すと時刻の精度が上がる（時刻はいつでも手入力で直せる）。

すでに入っている人が曜日の対象外だった場合（前日の内容を引き継いだときなど）は、その人だけ
「（利用曜日外）」というまとまりに入って一覧に残る。勝手に消えることはない。

選ぶと、その利用者の**住所と記号（車・補・玄）が自動で入る**。運行計画側が持っているのは
「号車ごとの利用者の並び」だけで、住所・記号・時刻はすべてマスタから導出される。

**住所欄は編集しない。** マスタからの自動表示に固定してある（行をつかんで並べ替える余地を広げるため）。
当日だけ迎え先が変わる場合は**備考欄**に書く。恒久的な変更はマスタを直す。

利用者名のプルダウンは**右クリックで空欄**に戻せる。

## 時刻の自動計算

各利用者の時刻は、**住所から移動時間を換算して5分刻みで自動入力**される。

事業所の出庫時刻を起点に、`前の停車地 → 次の停車地` の移動時間と乗降時間を積み上げ、5分単位に切り上げる。

```
到着時刻(n) = 切上5分( 到着時刻(n-1) + 乗降時間(n-1) + 移動時間(n-1 → n) )
```

- **移動時間** … 事業所を原点とする町の座標間の直線距離に迂回係数 1.35 を掛け、平均速度 22km/h で割る。
  番地からも微差を作るので、同じ町の中でも家ごとに差が出る。
- **乗降時間** … 標準3分。`車`（車椅子）＋3分、`補`（歩行器・車椅子）＋2分、`玄`（玄関先まで）＋1分。

これは実測値ではなく**モデルによる目安**で、地図データやルート API は使っていない（オフラインで動かすため）。
実距離に合わせたい場合は `TOWNS` を実座標に置き換えるか、`travelMin()` をルート API 呼び出しに差し替える。
`SPEED_KMH` `DETOUR` `DWELL` `STEP_MIN` はいずれも先頭にまとめてあるので、実績に合わせて詰められる。

### お迎え便は着時刻から逆算する

お迎えは「何時に事業所へ着きたいか」が先に決まるので、**着の目標から出発時刻を逆算**する。

1. その車の巡回（事業所 → 各家 → 事業所）に何分かかるかを積む。
2. 目標の着時刻から引いて、5分刻みに切り下げた時刻を出発時刻にする。
3. 各停車を5分刻みに切り上げるぶん着が後ろへずれるので、**目標に収まるまで5分ずつ早める**。

結果、**全車が 08:55〜09:00 に着く**時間割になる（月〜土の6日×8台で確認済み）。
午後は **13:10〜13:20**。**午前は 09:00、午後は 13:20 を超えない**のが決まりで、
逆算はこの上限を必ず守るところまで詰める。
出発時刻は車ごとにばらつく（所要の長いノア・リフト車は 07:40〜08:05 ごろ、
近場だけの車は 08:30 すぎ）。事業所が一度に混まないよう、着の目標は車ごとに1分ずつずらしてある。

出発時刻はカードの上端でいつでも書き換えられる。書き換えれば、そこから先が普通に前へ積み上がる。

### 着きたい時刻は車ごとに書ける

お迎え便では、カードの下端の **「目標」** に**何時に着きたいかを書ける**。
書けばその時刻から出発を逆算するので、**車ごとに余裕の持たせ方を変えられる**
（この車は 13:10 に戻す、この車は 13:20 でいい、など）。

- 空にすると自動に戻る。自動のときは幅の中で車ごとに少しずつずらして散らす
  （事業所に一度に着いて混まないようにするため）。
- 手で入れた目標は**便の色で表示**され、下線が実線になる。自動のままとは見た目で区別できる。
- 5分刻みなので目標ちょうどに着けないことがある。そのときだけ **（見込み hh:mm）** を脇に出す。
- 上限（午前 09:00／午後 13:20）より後を書いた場合は止めないが、**⚠ を付けて赤字**にする。
- `13:10` でも `1310` でも `13 10` でも入る。欄を離れると `13:10` の形に整える。

お送り便は事業所発が決まっているので、下端は帰着の **「目安」**（読むだけ）。

**午前お送りは帰着そのものを出さない。** 事業所へ戻らずそのまま午後お迎えへ回るため。
念のため手書きできる点線だけ残してある。

「デフォルトに設置」で組み直したときも、使う車の出発時刻をまとめて引き直すので上限は守られる。
目標の隣の **「実績」** は実際の着時刻を書くところで、こちらは空欄のまま。

### 手入力との関係

利用者の準備の都合などで調整できるよう、**時刻はいつでも手入力で上書きできる**。

- 手で入れた時刻には `※` が付き、自動計算では上書きされない。
- **その時刻を起点として、以降の行が繰り下がる。** 1人だけ遅らせれば後ろが自動で追従する。
- **空欄に戻すと自動計算に戻る。**

## 利用曜日との連動

利用者マスタの**利用曜日**（後述）が、送迎表の3か所に効く。

1. **既定の割り当て** … その曜日・その便に来る方だけがカードに並ぶ。
   月曜の午前便には「月曜のAM」に登録された方だけが入る。
2. **利用者名のプルダウン** … 同じ条件で絞られる。
3. **未割当** … その曜日・その便の名簿と突き合わせる。曜日の合わない方は最初から数えない。

日曜は利用曜日の対象外（月〜土のみ）なので、既定の割り当ては空になり、便の見出しにその旨が出る。
その日だけの特別運行を組みたいときは、プルダウンから直接選べば入力できる。

なお既定の割り当ては「いつもの号車」をそのまま使うので、曜日によっては1台あたり2〜3名と薄く散る。
実際の運用では台数を絞って組み直すことになる。

## 出欠（業務日誌の1枚目）

サイドバーの **「出欠」** で、その日の名簿に状態を付ける画面が開く（`#attend`）。
業務日誌の様式に合わせて **午前・午後を左右**に並べ、**要介護／介護予防**で分ける。
見出しには日誌と同じ `利用者数 n名（要介護 n　要支援 n　欠席 n）` を出す。

状態の語は**業務日誌の状態欄（I列・S列）のプルダウンをそのまま**使っている。

| 業務日誌の値 | 送迎表の行 |
| --- | --- |
| （空欄） | 通常 |
| 体調 / 受診 / 都合 / 入院 / SS | 欠席（理由としてそのまま出る） |
| 振替 | 振替利用（黄緑） |
| 新規 / 増回 / 再開 | 新規・増回（橙） |

**出欠と送迎表はつながっている。** 出欠で付ければ送迎表の行に出て、
送迎表の番号をクリックして変えれば出欠に戻る。
どちらか一方を正としないのは、事務所と車内のどちらからでも触るため。

保存は**利用者ごと・午前午後ごと**（車両カードではなく）。
乗る車が決まっていない方や、未割当の方も扱えるようにするため。
`day.<日付>` に一緒に入るので、日付を切り替えても残り、サーバー同期にも乗る。

要介護／介護予防の振り分けは**利用者マスタの介護度**を見る。
未設定の方は「介護度 未設定」としてまとめ、人数にも別に出す（埋め忘れが分かるように）。

## 業務日誌

サイドバーの **「業務日誌」** で、印刷レイアウトが業務日誌の面で開く（`#nisshi`）。
お預かりした様式の作りをそのまま紙に起こしてある。**A4横2枚**。

| 枚 | 中身 |
| --- | --- |
| 1枚目 | 業務日誌（氏名・運動・血圧・脈・体温・SPO2・備考・状態） |
| 2枚目 | 来所前 検温（氏名・検温欄） |

どちらの面も **午前・午後を左右**に置き、あいだを二重線で切る。
名簿は **要介護25行 → 介護予防（帯）→ 12行**。様式と同じ行数なので、
その日いない方のぶんも空欄が残り、手書きで足せる。番号は要介護から介護予防へ通しで振る。

見出しの `利用者数：n名（要介護者 n名　要支援者 n名）` は**出欠から数えて入る**（欠席は引く）。

| 欄 | どこから来るか |
| --- | --- |
| 氏名 | 出欠の名簿（ふりがな順） |
| 状態 | 出欠のプルダウン。赤字。欠席の方は氏名も赤に振る |
| 備考 | 利用者マスタの**血圧**。シャントだけ赤字 |
| 血圧 | `／` だけ刷る（上／下をその場で書き入れる） |
| 運動・脈・体温・SPO2・検温 | 空欄。当日その場で書き入れる |
| 勤務者・最終確認 | 空欄。様式どおりの記入欄 |

介護度が未設定の方は、様式に置き場がないので**要介護の段**に入れて数える。
そのままだと気付けないので、印刷レイアウトの説明文に**未設定の人数を赤字で出す**。

## 行の状態（左端の番号）

行の左端の番号をクリックするたびに、次の順で切り替わる。色だけで区別できるようにしてある。

| 状態 | 番号の色 | 見え方 |
| --- | --- | --- |
| 通常 | 便の色 | — |
| 欠席 | 赤 | 予定時刻から住所まで赤い取り消し線 |
| 振替利用 | 黄緑 | 番号のみ色が変わる |
| 新規・増回 | 橙 | 番号のみ色が変わる |
| 空白 | — | **利用者を外して行を空にする** |

最後の「空白」は状態ではなく操作で、押した時点で行が空になる（時刻・住所・記号も一緒に消える）。
他の車両に移すときに、プルダウンを開かずにその場で外せる。

**利用者がまだ入っていない行**では、これから入れる枠として **振替利用 → 新規・増回 → 通常** だけを回す
（欠席と空白は意味がないので出さない）。先に枠の色を決めてから人を選べる。

**欠席**には**理由**を付けられる。番号を欠席にすると、空になった「予定」の場所に
`体調 / 受診 / 都合 / 入院 / SS` のプルダウンが出る（業務日誌の状態欄と同じ語）。
欠席をやめると理由も落とす（前の理由が残って読み違えるのを防ぐため）。
取り消し線は理由を隠さないよう「実績」から住所までに引く。

**欠席**だけは乗車の扱いが変わる。

- **予定時刻は空欄になる。** 繰り上がった後続の時刻と紛れないようにするため。実績欄は残るので、
  当日連絡があった時刻などを書き込める。
- **その家をルートから外して時刻を引き直す**ので、以降の停車が繰り上がる。
- 集計では「◯名 欠席」に数え、乗車人数からは外れる。名簿には載っているので未割当にはしない。

**振替利用**と**新規・増回**は乗る人なので、乗車人数にも定員にもそのまま数える。番号の色だけが変わる。

## 並べ替え（ドラッグ＆ドロップ）

利用者の入っている行はつかんで動かせる。

- **同じ車の中**に落とすと、その位置に差し込まれて他の行が前後にずれる。
- **別の車**に落とすと、その車のその位置に移り、元の車は前に詰まる。移動先が満席なら断って何もしない。

行そのものではなく中身（利用者・時刻・住所・記号・状態）を入れ替えているので、
落とした後は時刻が引き直される。

マウス操作（HTML5のドラッグ＆ドロップ）なので、タブレットの指操作では動かない。
タッチでの並べ替えが要るようなら別途対応が必要。

## 印刷

ツール列の「送迎表を印刷」で印刷レイアウトが開く。**1便＝A4横1枚、合計4枚**
（午前お迎え／午前お送り／午後お迎え／午後お送り）。
業務日誌はサイドバーの「業務日誌」から、同じ画面の別のタブで出す。

紙のための見出しを別に足したりはしない。画面用の表題・日付の操作欄・ツール列だけが消え、
**画面と同じ便の見出しがそのままページの頭になる**。

```
午前 お迎え 自宅 → 事業所   8台 稼働 17名 登録者 …   通所介護事業所 デイサービス あさひ 令和8年7月27日（月曜日） 送迎表
```

便名・当日の人数・事業所名と日付が1行に収まるので、どの紙も単体で何の表か分かる。

その下に8台ぶんの車両カードと未割当の帯までが**1枚に収まる**ように寸法を詰めてある
（A4横・余白8mmで内寸 1047 × 733px。便の高さは 648px、1枚目は凡例が付いて 673px、
未割当の名前が多いときでも 697px）。
便は必ずページの先頭から始まり、途中で切れない（`break-before: page` と `break-inside: avoid`）。

### ページ数を環境で変えないための作り

紙の枚数が使う人の環境で変わると困るので、**高さを中身に任せない**作りにしてある。

- **車両の面は `height: 164mm` の決め打ち**。`grid-template-rows: repeat(4, minmax(0, 1fr))` で
  2列4段に割り、車両カードはその枠を分け合う。カードの中も flex で、
  `.route` が余りを取り `.stop` が等分するので、**行の高さが中身なりに伸びない**。
  便の高さの9割はこの決め打ちぶんなので、フォントが変わってもページ数は動かない。
  - Windows の游ゴシックは Linux/mac の代替フォントより行が高く、
    中身なりに組んでいたときは**行間が15%増えるだけで4枚が8枚に化けた**。
    いまは行間を30%増やしても4枚のまま。
- **印刷のときは `.sheet` を flex から通常のブロックに戻す**。
  flex コンテナの中では改ページ指定を無視するブラウザがあり、便が1枚に収まらない原因になるため。
- **`.fleet` の2列組みは印刷側で指定し直す**。画面幅が狭いときの1列表示が紙に持ち込まれないようにするため。
- **記号の凡例（下部の小さい文字）は1枚目だけ**。2枚目以降は同じ説明を繰り返さない。
- 未割当の帯は紙では**1行**に丸める。全員ぶん確かめたいときは画面で見る。
- 乗車0名で畳んだ車両カードも畳んだまま出る。手書き用に空の車を残したいときは印刷前に **＋** で開く。

### 紙の色

紙の上でこそ便の違いが効くので、画面よりインクを一段濃くしてある。
`print-color-adjust: exact` を全体にかけているので、
**ブラウザの「背景のグラフィック」を切っていても地色は出る**。

- **便の見出しは、その便の色を敷いた帯**（濃い地に白抜き）。どの便の紙か離れていても分かる。
- **車両カードは1台まるごと便の色**。縁と左袖が濃い色、袖の中と事業所着の帯が中間、
  カードの地とルートの一行おきがごく薄い色。段ごとの塗り分けで、名前から備考まで目が横に流れる。
- **車椅子の方が乗るリフト車だけ朱**。カードごと色が変わるので、8台の中から一目で拾える。
- 号車・出発位置・運転手・実績・備考など、**書き入れる欄は白のまま**。上から鉛筆で書ける。
- 書き入れる欄の点線は、刷ったときに消えない濃さにしてある。

### 「印刷」は印刷レイアウトを開く

「送迎表を印刷」を押すと、**刷り上がりの紙をそのまま並べた画面**（`#print`）に切り替わる。
灰色の台の上に A4横の紙が置かれ、右下に `1 / 4　午前お迎え` … と入る。
紙は窓の幅に合わせて縮むだけで、中身は印刷とまったく同じ寸法。刷る前に目で確かめられる。

この画面は**送迎表と業務日誌の両方**を扱う。頭のタブで切り替える。

| タブ | 枚数 |
| --- | --- |
| 送迎表 | A4横・4便で4枚（`#print`） |
| 業務日誌 | A4横・日誌と検温で2枚（`#nisshi`） |

その画面のボタンは3つ。

| ボタン | すること |
| --- | --- |
| この n 枚を印刷 | 別タブ → ファイル保存 → 枠のまま印刷、の順に通る道を試す |
| ファイルに保存 | 印刷用ページをファイルで受け取る |
| 送迎表へ戻る | 元の画面へ |

紙の組み方（`build`）だけを差し替えれば刷るものを増やせるようにしてある。
別タブ・ファイル保存・案内の文言は、選んでいるものに合わせて出る。

### なぜ回りくどいか

送迎表がプレビューの枠（iframe）の中に置かれていると、**枠の中の改ページ指定は親ページの印刷に届かない**。
親からは中身が「1枚の長い絵」に見えるだけなので、用紙の高さで機械的に切られ、
車両カードが行の途中で割れ、枚数も合わない。実測でも**同じ内容が 最上位＝4枚／枠の中＝5枚**になった
（Edge では4便が3枚になっていた）。枠の外＝最上位のページとして組ませれば
`@page` も `break-before: page` もそのまま効く。だから印刷は必ず枠の外へ出す。

- 印刷用ページは**その時点の表の写し**。運転手・利用者・手書きした時刻や備考もそのまま持っていく
  （`select` の選択は複製に乗らないので、選ばれている `option` に印を付け直している）。
- 画面用の操作列・振替の受付欄・保存の表示は落とし、4便すべてを開いた状態にする。
- 紙の見た目は `@media print { … }` の中身を取り出して画面にも当てているので、
  **規則は1か所にしかない**。プレビューと実際の刷り上がりが食い違わない。
- 題名が `令和8年7月27日（月曜日）送迎表` になるので、「PDF に保存」したときのファイル名もそれになる。

### 枠の中で別タブも開けないとき

claude.ai のプレビューの枠はポップアップも素のダウンロードも塞いでいるので、
そのときは **claude.ai の保存の口（`window.claude.downloads`）**から印刷用ページをファイルで渡す。
確認のダイアログが出て、承諾すると `令和8年7月27日（月曜日）送迎表.html` が保存される。開いて印刷すれば4枚。

- `html` が許可されていない環境では `.html.txt` で渡す。末尾の `.txt` を消せば開ける。
- 断られた・混み合っているなど、返り方ごとに案内を分けている。
- どれも通らなかったときだけ、最後に枠のまま印刷を試す（4枚にならない旨を添えて）。

## 記入をクリア

ツール列の「記入をクリア」は、**いま開いている便**についてダイアログを開く。
車両ごとの乗車人数を見ながら、**どの車両の利用者を取り消すか**を選ぶ（乗車0名の車両は押せない）。
ダイアログの下の「この便の全車両の利用者を取り消す」で便まるごとも消せる。やり直しは「一つ戻る」。

取り消すのは利用者の行（利用者・時刻・実績・記号・備考・状態）だけで、
号車・運転手・事業所着の記入と、他の便・他の日付には触れない。

## 未割当（画面の左に固定）

乗せ忘れは紙に出てから気づいても遅いので、**未割当は画面の左に貼り付けて常に見えるように**してある。
上に便の切替、その下に人数、下に名前が並ぶ。スクロールしても付いてくる。

- 名前を**車両カードへドラッグ**すると乗る。カードのどこに落としても空いている末尾に入り、
  行の上に落とせばその位置に差し込まれる（先にいる方は後ろへずれるだけで消えない）。
  定員がいっぱいの車は断って理由を出す。畳まれていたカードは開く。
- **押す**とこれまでどおりダイアログが開き、車両ごとの `乗車 n / 定員` と `空き◯行` を見ながら選べる。
- 便を切り替えると、その便の未割当に入れ替わる。
- 印刷ではサイドバーは出ない。紙は従来どおり便の下の帯が担う（1行に丸める）。

これに伴い、**画面の上に貼り付くのは便の見出しの行（便名・経路・人数）だけ**にした。
表題やツール列は上へスクロールすれば出てくる。便の切替はサイドバーからいつでもできる。

サイドバーのいちばん下に **「出欠」「業務日誌」「マスタ編集」** の3つを置いてある。
日々のツール（配車・元に戻す・印刷など）とは性質が違う「別のページへ行く」操作なので、
ツール列から外して見た目も分けた（絵＋2行の説明）。
朝は上から順に、出欠を付ける → 業務日誌を刷る、と辿れる並びにしてある。

## 配車マスタと「デフォルトに設置」

出勤する職員の人数で動かす車の台数が変わるので、**人数版ごとに使う車両**を配車マスタに持たせてある。

| 人数版 | 既定で使う車両 |
| --- | --- |
| 5人版 | 1〜3号車枠・ノア・リフト車 |
| 6人版 | 1〜4号車枠・ノア・リフト車 |
| 7人版 | 1〜5号車枠・ノア・リフト車 |
| 8人版 | 全8台 |

ツール列の `[◯人版] デフォルトに設置` で、**いま開いている便**をその版に組み直す。
確認は挟まない（やり直しは「一つ戻る」）。結果は画面下の通知で知らせる。

組み直しの順番は次のとおり。

1. その人数版の、**その曜日・その便に保存してある割り当て**があれば、まずそのとおりに乗せる。
2. 残った方のうち**車椅子の方はリフト車へ**。
3. さらに残りを、使う車へ**均等に**配る（並び順を保つので地区のまとまりは崩れない）。
4. 使う車の**出発時刻を引き直す**ので、着は上限の内側に収まる。
5. 収まりきらなかった方がいれば人数を知らせるので、未割当の欄から乗せる。

### 割り当ては 人数版 × 曜日 × 便 で持つ

自動の均等配分だけでは職員の判断（この人とこの人は同じ車、この地区は先に回る…）が入らないので、
**割り当てを保存**できるようにしてある。顔ぶれは曜日で変わり、行きと帰りで回り方も変わるので、
保存の単位は **人数版 × 曜日（月〜土）× 便（午前お迎え／午前お送り／午後お迎え／午後お送り）**。

マスタ編集の「配車」タブで人数版の行の **「編集」** を開くと、
**曜日のタブ**と**便のタブ**が出る（タブには入っている人数が付くので、どこを埋めたか一目でわかる）。
開いたときは、いま送迎表で見ている曜日と午前お迎えが選ばれている。

いちばん速いのは**うまく回った日の便をそのまま取り込む**流れ。

1. 送迎表でその日を開き、`[◯人版] デフォルトに設置` と手直しで並びを整えておく（保存済みの日ならそれでよい）。
2. マスタ編集 → 配車 → その人数版の「編集」→ 曜日と便のタブを選ぶ。
3. **「取り込み元」の日付**を選んで **「この便を取り込む」**。
4. 「保存して送迎表へ戻る」。

以後、**同じ曜日・同じ便**で「デフォルトに設置」すると保存した並びが再現される。

### 取り込み元の日付

取り込み元のプルダウンには、**開いている曜日と同じ曜日の保存済みの日付だけ**が新しい順に並ぶ。
月曜のタブなら月曜の日付しか出ない（曜日ごとに顔ぶれが違うので、他の曜日を混ぜても使えないため）。
いま画面で見ている日は `（表示中）` が付いて最初から選ばれている。まだ保存がなければ
「保存済みの◯曜がありません」と出てボタンは押せない。

- **「この便を消す」** … その曜日・その便の割り当てだけを空にする。
- 欄の中でも直接いじれる。車両ごとに `＋ 追加` で人を入れ、チップの `◀ ▶` で順番を動かし、`×` で外す。

取り込みは**その人数版で使う車両ぶんだけ**。使わない車に人が乗っていた場合は取り込まずに知らせるので、
先に台数を合わせてから取り込んでほしい（人数版の台数が勝手に増えないようにしている）。
日曜は利用曜日の対象外なので取り込めない。

## 振替利用者の受付

便の見出しの中に **振替利用** の受付欄がある（`▾` の付いた入力欄）。氏名を打つと利用者マスタから候補が出るので、
選んで「＋ 振替に追加」でその日の振替名簿に載る（午前・午後それぞれ）。追加した方はチップで並び、`×` で外せる。

行の番号を **振替利用（黄緑）** にすると、その行の**利用者名プルダウンは振替名簿の方だけ**になる。
通常に戻せば元の一覧に戻る。すでに選ばれている方は名簿の外でも消えない。

**振替に追加した方は、その便の「未割当」に載る。** どの車にも入っていない状態なので、
赤い帯の名前を押してそのまま車両を選べる。

振替名簿は日付ごとに保存される。

## 乗車0名の車両カード

**乗車0名の車両カードは自動で1行に畳まれる。** その日に動く車だけが目に入るようにするため。
畳まれたカードには `号車／人数と定員／理由（利用者なし・全員欠席◯名）` が出る。

畳まれたカードは**一覧の末尾へ回す**ので、動く車だけが前に詰まって左右がそろい、
畳んだぶんの余白も出ない。

- **＋** で開く。開いたカードは、こちらで畳み直すまで開いたままになる。
- 開いた状態のカードには **−** が出て、また畳める。
- 畳んだ状態は印刷にも反映される。空車のぶんだけ紙が詰まるので、
  手書き用に空の車両を残したいときは印刷前に **＋** で開いておく。

## 人数の見方

便のヘッダに7つ並ぶ。

| 項目 | 意味 |
| --- | --- |
| 稼働 | 実際に人を乗せる車の台数。**乗車0名の車は数えない** |
| 登録者 | 乗車＋欠席。その便に載っている人の合計。便の見出し色で表示する |
| 乗車 | 実際に乗る人数 |
| 欠席 | 欠席に切り替えた人数。1名以上で赤くなる |
| 振替 | 振替利用に切り替えた人数。1名以上で黄緑になる。乗る方なので「乗車」にも含まれる |
| 未割当 | その曜日・その便の名簿にいて、どの車にも入っていない人数。1名以上で赤くなる |
| 重複 | 同じ人が2台に入っている件数。1件以上で赤くなる |

## マスタ編集

ツール列の「マスタ編集」から**別ページとして開く**（送迎表と入れ替わる、`#master` が付く）。
再読み込みしても開いたまま、ブラウザの戻るでも送迎表に戻れる。中は3つのタブに分かれている。

- **利用者** … 氏名・ふりがな・町名・住所・記号・**利用曜日**を編集、行の追加。
  一覧は**ふりがなの五十音順**。町名は座標を持っている町からの選択
  （新しい町を足すには `TOWNS` に座標を書く）。
- **運転手** … 氏名と**出勤日**の編集、追加と削除。
- **配車** … 人数版（5〜8人版）ごとに動かす車両を選ぶ。

編集は下書きに溜まり、**「保存して送迎表へ戻る」**で反映される。
**「変更を破棄して戻る」**なら何も残らない。

### 追加・終了・削除はダイアログで

**「＋ 利用者を追加」** を押すとダイアログが開き、`氏名 / ふりがな / 住所 / 介護度 / 記号 / 利用曜日` を
まとめて入れられる（氏名だけ必須）。表に空行が生えるより、何を入れるかが分かりやすいため。

**「終了」** もダイアログで `終了日 / 終了理由` を聞く。ボタンと利用終了の枠は**青系**。
**「削除」** は消える内容を出したうえで確認する。ボタンと確定は**赤**。
終了と削除は結果がまるで違うので、色で取り違えを防いでいる。

いずれも `confirm()` は使わない。埋め込み表示では黙って無視されるため、確認は必ず画面の中で行う。

### 利用終了

利用者の行の **「終了」** を押すと、その方は **利用終了** の表へ移る。終了日（既定は本日）と理由を書ける
（入院・施設入所・他事業所へ・転居・逝去・自己都合などの候補が出る）。

終了にした方は、送迎表の**利用者プルダウン・既定の割り当て・未割当・振替の候補**から外れる。
記録は残るので、**すでに表に入っている過去の日付ではそのまま**表示される。
**「利用中に戻す」**でいつでも戻せる。

行ごと消す **「削除」** も残してあるが、履歴を残したいなら「終了」を使う。

### 利用曜日（利用者）

月〜土の6枠。押すたびに **なし → AM → PM → なし** と切り替わり、選んだ枠には曜日の下に
`AM`（藍）か `PM`（柿渋）が出る。午前の部に来る日と午後の部に来る日を1つの枠で表せる。

同じ方が同じ日に午前と午後の両方に来る運用があるなら、この循環に「終日」を足す形になる。

### 出勤日（運転手）

同じ形の6枠で、こちらは **なし → AM → PM → 終日 → なし** と回る。
色は AM＝藍、PM＝柿渋、**終日＝黄緑**。「なし」の枠と見分けがつくよう、終日にも色を当ててある。

車両カードの運転手プルダウンには、**その曜日・その便に出勤する方だけ**が並ぶ（終日はどちらの便にも出る）。
すでに選ばれている方が出勤日から外れた場合は「（出勤外）」として一覧に残る。

保存すると利用者は五十音順に並び替わるので、利用者名のプルダウンも町ごとに五十音順になる。

「保存して閉じる」でマスタが保存され、全4便の利用者・運転手プルダウンと時刻が引き直される。
氏名が空の行は保存時に捨てる。削除した利用者が割り当てられていた行は空欄になる。

## 記入ミスを拾う仕組み

行数＝定員なので、5人乗りは4行・7人乗りは6行を必ず描画する。空席が「見えないもの」ではなく
「見えるもの」として残るため、当日の追加受入の余地が一目でわかる。そのうえで、

- **定員超過**：定員を超えて名前を入れると、ピップと合計欄が警告色になり `⚠ 定員超過` が出る。
- **重複**：同じ便のなかで同じ利用者が2台に入っていると、両方の行が警告色になり「◯件 重複」に数えられる。
  片方を空欄に戻せば、その場で両方の警告色が消える。
- **未割当**：その曜日・その便に来る方の名簿と突き合わせ、どの車にも乗っていない人を
  便の下に名前つきで並べる。乗せ忘れがそのまま紙に出るので、印刷前に気づける。
  全員が未割当のとき（白紙のとき）は「未割当 ◯名（名簿全員）」の一行に畳む。

## 記号

| 記号 | 色 | 意味 | 車両への影響 |
| --- | --- | --- | --- |
| 車 | 山吹 | 車椅子（リフト・スロープ使用） | **リフト車のみ** カードが朱色になり定員が1名減る |
| 補 | 藍 | 歩行器・車椅子持参もしくは貸出 | — |
| 玄 | 松葉 | 玄関先まで送迎 | — |

マスタから自動で入るが、行ごとにクリックで切り替えられる。印刷しても薄い枠が残るので手書き追記もできる。

## 使い方

- 時刻・住所・号車・事業所着はクリックしてその場で書き換えられる（貼り付けは書式を落として挿入）。
- 「記入をクリア」は**その日の**全4便の記入をまとめて消す（確認ダイアログあり）。取り消しはできない。
  他の日付の内容には触れない。
- 「送迎表を印刷」で全4便がA4横4枚、サイドバーの「業務日誌」で日誌と検温のA4横2枚として出力される。
  便の色は「背景のグラフィック」を切っていても出る。
- 空欄の行は時刻・利用者名・住所に点線が入るので、印刷後に手書きで足せる。

## データの差し替え

`index.html` のスクリプト先頭にある定数を書き換える。

```js
// 車両。seats は車検証上の乗車人数で、定員は seats - 1（運転手を除く）で自動計算される。
// name を持つ車両は号車の記入枠のかわりにその名前を表示する
// lift: true の車両だけ、記号「車」で定員が1名減る
const FLEET = [{ seats: 5 }, …, { seats: 7, name: "ノア" }, { seats: 7, name: "リフト車", lift: true }];

// 運転手マスタの初期値。同じく画面から編集できる
const DEFAULT_DRIVERS = ["佐藤 健一", "佐々木 実", …];

// 便。depart は各カードの事業所発の初期値で、時刻計算の起点になる
const LEGS = [{ key: "am-pick", part: "am", partLabel: "午前", dir: "お迎え", depart: "08:15", … }, …];

// 町の座標（事業所が原点、単位km）。移動時間の換算に使う
const TOWNS = { "中央町": { x: 0.8, y: 0.6 }, … };

// 利用者マスタの初期値。画面から編集した内容が保存されていればそちらが優先される
const DEFAULT_USERS = [
  { id: "u01", name: "田中 ハル", kana: "たなか はる", town: "中央町", addr: "中央町3-14-2",
    tags: ["補"], days: { "月": "AM", "水": "AM", "金": "AM" } }, …
];

// 号車ごとの「いつもの担当」。並び順がそのままお迎えのルート順で、お送りは自動で逆順になる。
// 実際に並ぶのは、この中でその曜日・その便に来る方だけ
const ASSIGN = { am: { 1: ["u01", "u02", "u03", "u04"], … }, pm: { … } };
```

台数を増減した場合も `FLEET` の要素数に追従してカードが生成される。

マスタを画面から編集すると保存された内容が優先される。コード側の初期値に戻したいときは、
ブラウザの localStorage から `soutei.v2.users` と `soutei.v2.drivers` を消せばよい。

収録している利用者名・住所はすべて動作確認用の架空データ。
