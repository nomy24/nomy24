# デイサービス送迎表

車両8台（5人乗り6台・7人乗り2台）の送迎ルートを、**午前・午後 × お迎え・お送りの全4便**として管理する運行表。
印刷すると1便＝A4横1枚、合計4枚になる。
`index.html` の1ファイルで完結（外部CSS・JS・フォントなし）。ブラウザで開いてそのまま印刷できる。

## 4便の構成

| 便 | 経路 | 標準時間帯 | 色 |
| --- | --- | --- | --- |
| 午前 お迎え | 自宅 → 事業所 | 08:30–09:50 | 藍 |
| 午前 お送り | 事業所 → 自宅 | 12:05–13:25 | 柿渋 |
| 午後 お迎え | 自宅 → 事業所 | 13:00–14:10 | 青碧 |
| 午後 お送り | 事業所 → 自宅 | 16:35–17:45 | 臙脂 |

色は**寒色＝お迎え／暖色＝お送り**で揃えてある。運転手が最初に確認するのは進行方向なので、
そこを色相に、午前・午後を色の系統に割り当てた。刷り上がった4枚を取り違えにくくするための区別でもある。

画面ではタブで切り替え、印刷では4便が別ページになる。日付・便名・合計は各ページのヘッダに入る。

## レイアウトの考え方

送迎表は「時間割」ではなく「車ごとの巡回順」なので、時刻をタテ軸に取ったマトリクスではなく
**車両カード×8を2列に並べる**構成にした。

各カードは左右2カラム。

- **左**：号車番号／乗車定員／運転手／ナンバー、そして定員ピップ（`■`＝乗車・`□`＝空席）
- **右**：ルート順の行リスト（`順番 / 時刻 / 利用者名 / 住所 / 記号`）と、事業所着（帰着）の時刻

要件との対応は次のとおり。

| 要件 | 表現 |
| --- | --- |
| 利用者名 | 各行の主要素。利用者マスタからプルダウンで選ぶ |
| 送迎時間 | 各行の先頭に配置。`tabular-nums` で桁を揃え、上から下へ時系列に読める |
| ルート順 | 丸数字を縦線でつないだ経路線。順番＝行順そのもの |

## 利用者の選択と住所の自動反映

利用者名の欄は利用者マスタ（`USERS`）を引いたプルダウン。**町名ごとの optgroup** にまとめてあるので、
ルートを組む順序（地区をまたがない）のまま選んでいける。

選ぶと、その利用者の**住所と記号（車・介・玄）が自動で入る**。運行計画側が持っているのは
「時刻」と「利用者ID」だけで、住所と記号は常にマスタから引き直される。
住所を直したいときはマスタを直せば全4便に反映される。

当日だけ迎え先が変わる場合（病院から、家族宅からなど）は住所欄をその場で書き換えられる。
マスタと違う値になった行には `※` が付き、印刷にも残る。別の利用者を選び直すと元に戻る。

## 記入ミスを拾う仕組み

行数＝定員なので、5人乗りは4行・7人乗りは6行を必ず描画する。空席が「見えないもの」ではなく
「見えるもの」として残るため、当日の追加受入の余地が一目でわかる。そのうえで、

- **定員超過**：定員を超えて名前を入れると、ピップと合計欄が警告色になり `⚠ 定員超過` が出る。
- **重複**：同じ便のなかで同じ利用者が2台に入っていると、両方の行が警告色になり「◯件 重複」に数えられる。
- **未割当**：午前・午後それぞれの利用者名簿（`ROSTER`）と突き合わせ、どの車にも乗っていない人を
  便の下に名前つきで並べる。乗せ忘れがそのまま紙に出るので、印刷前に気づける。

## 使い方

- 時刻・住所・事業所着の時刻はクリックしてその場で書き換えられる（貼り付けは書式を落として挿入）。
- 「印刷」で全4便がA4横4枚として出力される。ブラウザの印刷設定で「背景のグラフィック」を有効にすると、
  号車欄の地色とヘッダの帯が印刷される。
- 空欄の行は時刻・利用者名・住所に点線が入るので、印刷後に手書きで足せる。
- 記入内容はページを閉じると消える。日々の記録として残す運用なら、印刷またはPDF保存を前提にしてほしい。

## データの差し替え

`index.html` 末尾のスクリプトにある4つの定数を書き換える。

```js
// 車両。seats は車検証上の乗車人数で、定員は seats - 1（運転手を除く）で自動計算される
const FLEET = [
  { no: 1, seats: 5, plate: "品川 500 あ 12-34", driver: "佐藤 健一" },
];

// 利用者マスタ。プルダウンの選択肢であり、住所と記号の供給元
const USERS = [
  { id: "u01", name: "田中 ハル", kana: "たなか はる", town: "中央町", addr: "中央町3-14-2", tags: ["介"] },
];

// 午前の部・午後の部それぞれの利用者。未割当の検出に使う
const ROSTER = { am: ["u01", …], pm: ["u34", …] };

// 便ごとの運行計画。stops の並び順がそのままルート順
const PLAN = {
  "am-pick": { runs: { 1: { arrive: "09:35", stops: [{ t: "08:35", id: "u01" }, …] } } },
};
```

`PLAN` のキーは `am-pick` / `am-drop` / `pm-pick` / `pm-drop` の4便、`runs` のキーは号車番号。
台数を増減した場合も `FLEET` の要素数に追従してカードが生成される。

収録している利用者名・住所・車両番号はすべて動作確認用の架空データ。
